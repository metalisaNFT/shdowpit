# SHDOWPIT — Maestro Audit

**Date:** 2026-08-29 · **Commit audited:** `840a56c` (`Close god layer payoff loop…`, == `origin/main`) · **Method:** the Maestro flow (Logician → Maestro → Polymath), with the Polymath's Detail Sentinel pass fanned out over seven slices of the codebase · **Scope:** the whole game — `src/` (175 files, 55.6k LOC), `server/`, `local-ai-engine/`, `tools/`, docs · **Code changes made:** none.

> **Verdict in one paragraph.** The bones are sound: the combat resolution point is single, the key never enters the browser, the save is versioned and migrates, the god layer's utility engine, memory writer and Book all hold as documented, and VFX/lights/rigs obey their pooling rules. What has drifted is the *seams* — the modal/offer queue, the run-end funnels, the heat state machine, the harness layer that is supposed to prove all of this, and a set of promises (powers, signatures, previews, docs) the code no longer keeps. Four items will freeze or wipe a normal player's session (REROLL on any offer, Esc on the build screen, NEW WORLD, and the proc chain that turns most roguelite powers off after three hits). Six of the sixteen pass/fail harnesses are red on the reference environment today, and the ones that are green include several that cannot fail. Fix the four freezes and the verification layer first; everything else can then be done with a net under it.

### Assumptions (stated so they can be rejected)
- The owner's project notes and `docs/` describe *intended* behaviour; where code and note disagree, the disagreement itself is a finding, not a verdict about which side is wrong.
- The GitHub `main` at `840a56c` is byte-identical to `F:\ShdowPit` (the local reflog's HEAD sha matches the remote; uncommitted local edits could not be seen).
- "Player-visible" means the DESCEND ALONE and THE LONG GAME loops as shipped, not the F1/debug paths.

### Constraints
- No code changes; no file under the repo modified (the harness battery wrote screenshots into tracked `*-shots/` folders — itself a finding, §4.3 T-8 — in the clone only).
- Every finding carries `path:line` evidence and a `verified` / `suspected` tag. `verified` means the reviewer traced the path end-to-end, or reproduced it (four findings were reproduced live: the proc-chain saturation, the standalone server crash, the any-origin `/api/ai/connect`, and the REROLL/Build-screen freezes were re-read line by line by the Maestro).
- The owner's stated invariants are the yardstick; the audit checks each one and reports which hold.

### Logical relationships and dependencies
- The verification layer gates everything else: while `test:wiring` cannot fail, `godtest` compares two fields of one intervention, and six suites are red by default, no fix below can be *proven* to stay fixed. That makes "make the harnesses honest" a dependency of every other phase, not a cleanup item.
- The offer/modal queue (`requestModal`, the five `setTimeout` offers, the five run-end exits) is one mechanism with six symptoms (REROLL freeze, Build freeze, dropped trophies/shards/powers, lost succession, stale `descent`, pointer lock after extraction). Fixing them one symptom at a time will re-break each other; they are one work package.
- Heat, encounter director, toast gate and the intro card share one hidden state (`encounter.busy` / `intro.active` / `lockedExits`); each is wrong in the same shape — a flag with one writer and no release.

### Risks and contradictions surfaced
- Intake premise "every harness clicks `#title-start`" — false. Premise "`#ai-layer` is the topmost child of `#ui` and hidden outside playing/dying" — false (`Game.ts:363-373, 2322-2329`). Premise "the wiring audit's P0/P1 gaps are open" (stated by the Maestro in the scoping question) — false; they were fixed on 08-28/29 and the doc is stale. Premise "`localStorage` is touched by `AIBackend`/`AISettingsPanel`" — false (comments only). Premise "20 `Math.random` sites" — 83.
- THE RULE ("an intervention may never set an outcome; `RAISE` is the single exception") is stronger than the code: `gift` adds +7 `power`, `calamity` adds a living captain.

### Confidence
High on the P0s and on the harness/documentation findings (reproduced or re-read by the Maestro). Medium-high on the P1 simulation findings (traced, several confirmed with node harnesses over hundreds of turns by the reviewer, none observed in a human play session). Medium on the two `suspected` crash/UX paths (`situationAreaId` recursion, NemesisIntro stale timeout) — the mechanism is exact, the trigger state is runtime-dependent.
